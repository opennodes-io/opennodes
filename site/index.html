OpenNodes Protocol · ONP Draft 0.1

The discovery layer for AI inference

MCP standardized how AI reaches tools. The OpenAI API shape standardized invocation. x402 standardized machine payments. Nothing standardizes how a client finds an inference endpoint it doesn't already know — what model it serves, on what hardware, at what price, and whether it's honest. OpenNodes fills exactly that gap, and composes the rest from existing standards.

The loop

Discover → verify → estimate → invoke → receipt

NODE CARDAny provider self-describes at /.well-known/open-node.json: models, hardware, benchmarks, per-token price — signed, revisioned.
REGISTRYOpen registration with DNS/HTTP namespace proof; searchable across registered nodes and imported catalogs (OpenRouter, Hugging Face, models.dev).
VERIFYAdmission probes earn trust tiers: identity fingerprinting (serve what you claim), context verification with capping, capacity ramps, continuous blind probes.
ESTIMATEPre-price a whole multi-model chain; estimates pin card revisions, so the quoted price is enforceable at invocation — never a surprise on the bill.
RECEIPTEvery response carries a signed usage receipt: amount = usage × pinned price. The audit trail for settlement and disputes.

Why it's different

Verified, not just ranked

Anyone can list. No one is trusted blindly.

A university cluster, a sovereign EU cloud, your own Ollama box — same automated admission gate for everyone. Claiming a model you don't serve gets you marked disputed and delisted.

Transparent ranking, by rule.

Every search result carries its rank explanation — component weights and values. Undisclosed ranking inputs are non-conformant. Claimed, measured, and attested values are never blended.

Out of the data path.

Discovery is metadata; invocation goes direct from client to node. Your prompts don't transit anyone's middlebox — which is why data-residency deployments can actually use it.

Federated by construction.

The registry is a protocol, not a place: an OpenAPI anyone can implement, plus a signed, mirrorable export feed. Node Cards live at the node's origin — no registry owns the data.

Quickstart

Three ways in

Model search & chain pricing inside your editor (MCP)

git clone https://github.com/opennodes-io/opennodes && cd opennodes/impl && npm install
node packages/registry/bin.js                # registry on :4300
node packages/cli/bin.js mcp --print-config  # paste into Cursor / VS Code / Claude Desktop

Any OpenAI-compatible app, routed through discovery (gateway)

node packages/cli/bin.js gateway --port 4141 --virtual "auto-cheap=modality=text&sort=price"
# point the app's OpenAI base URL at http://127.0.0.1:4141/v1

Serve your own model as a node (Python kit, engine untouched)

pipx install ./node-kit
onp-node init --engine http://127.0.0.1:11434/v1 --id org.example.mybox --public-url https://ai.example.org
onp-node serve && onp-node check && onp-node register https://registry.example.org
