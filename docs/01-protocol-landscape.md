# Protocol & Standards Landscape for AI Model/Agent Discovery and Communication (as of August 2026)

Research report evaluating overlap between the proposed "AI Nodes" concept (a federated registry + discovery service for AI compute resources — LLMs, diffusion models, etc. — with model metadata, benchmarks, GPU/pricing info, invocation, and bridging to MCP/WebMCP) and existing standards work.

---

## 1. Model Context Protocol (MCP) and the Official MCP Registry

**What it standardizes.** MCP is a JSON-RPC protocol for connecting AI applications (hosts/clients) to *tools, resources, and prompts* exposed by servers. It answers "how does a model-powered app call external capabilities," not "how do you find or invoke a model."

**Status/governance.** Open governance under the MCP steering/core maintainer structure (originated by Anthropic). Current stable spec version is **2025-11-25**; the **2026-07-28 release** (RC locked May 21, 2026) is MCP's largest revision since launch: a stateless protocol core (no `initialize` handshake, no `Mcp-Session-Id`, load-balancer friendly), a formal extensions framework with reverse-DNS identifiers (first official extensions: **MCP Apps** and **Tasks**), OAuth 2.0/OIDC-aligned authorization hardening, and — notably — **deprecation of Roots, Sampling, and Logging** with a 12-month removal window. The deprecation of Sampling means MCP is moving *away* from even its indirect model-inference pathway (sampling let servers request LLM completions via the client). ([MCP blog: 2026-07-28 RC](https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/))

**The official MCP Registry** ([registry.modelcontextprotocol.io](https://registry.modelcontextprotocol.io/), [about page](https://modelcontextprotocol.io/registry/about), [GitHub](https://github.com/modelcontextprotocol/registry)):
- Still officially **in preview** ("breaking changes or data resets may occur before GA"), though the **API froze at v0.1 in October 2025**. Backed by Anthropic, GitHub, PulseMCP, Microsoft.
- Hosts **metadata about MCP servers only**, in a standardized `server.json`: reverse-DNS name (`io.github.user/server`), package location (npm/PyPI/Docker) or remote URL, execution instructions, description/capabilities.
- Namespace authentication via GitHub/DNS/HTTP challenges; it is a **meta-registry** — deliberately unopinionated metadata, no code hosting, no security scanning (delegated to package registries and downstream aggregators), **no ratings/rankings/curation** (explicitly left to downstream aggregators/marketplaces), designed to be consumed by aggregators, not directly by host applications. It publishes an OpenAPI spec other registries can implement (a federation-by-interface model, not federated replication).

**What it does NOT cover.** Nothing about model/inference discovery: no model names, parameter counts, benchmarks, GPU resources, pricing, per-token billing, or ranking. It is a registry of *tool servers*, not *models*. Private servers are explicitly out of scope.

**Gap vs. AI Nodes.** MCP + Registry cover the "publish metadata once, let clients discover" pattern and the tool-invocation side that AI Nodes would bridge to — but the registry's subject matter (tool servers) is disjoint from AI Nodes' subject matter (inference endpoints/models). Its registry architecture (server.json schema, namespace auth, OpenAPI-based sub-registries) is nonetheless the closest design template for what AI Nodes proposes.

## 2. WebMCP

**What it standardizes.** A browser JavaScript API (`navigator.modelContext` / `document.modelContext` in the explainer) letting web pages register in-page "tools" with natural-language descriptions and structured schemas so agents can call site functionality directly instead of scraping the DOM. Explicitly designed to *complement* backend MCP. ([webmachinelearning/webmcp](https://github.com/webmachinelearning/webmcp))

**Governance/maturity.** Incubated in the **W3C Web Machine Learning Community Group** (accepted September 2025); it is a **Draft Community Group Report**, not a W3C standard. Chrome has the only working implementation, running a **public origin trial (Chrome 149–156)**; Edge support unconfirmed despite Microsoft co-authoring; Firefox/Safari engaged but uncommitted. Mid-2026 assessments describe near-zero real-site deployment and no mainstream agent consuming the tools yet. ([State of WebMCP, July 2026](https://www.spronta.com/blog/state-of-webmcp-july-2026/), [compatibility status](https://dev.to/ai-agent-economy/webmcp-in-2026-which-browsers-support-navigatormodelcontext-complete-compatibility-status-1oe4))

**Gap vs. AI Nodes.** WebMCP is purely a *client-side tool exposure* surface — no registry, no model metadata, no inference. Relevant to AI Nodes only as a bridge target ("invoke discovered nodes against WebMCP-enabled sites"), which no existing standard addresses; note the bridge would depend on a spec that is itself pre-standard and barely deployed.

## 3. Google Agent2Agent (A2A)

**What it standardizes.** Peer-to-peer communication between opaque agents: task lifecycle, messages/artifacts, streaming, push notifications, over three bindings (JSON-RPC 2.0, gRPC, HTTP/REST) with a canonical protobuf data model. Discovery is via the **Agent Card**, a signed JSON document (identity, provider, capabilities, security schemes, service endpoint, skills, extensions) served at **`/.well-known/agent-card.json`** — a URI reportedly registered with IANA. Extended discovery via registries/curated catalogs is acknowledged but not specified normatively. ([Spec, v1.0.0](https://a2a-protocol.org/latest/specification/), [GitHub](https://github.com/a2aproject/A2A))

**Governance/maturity.** Donated by Google to the **Linux Foundation** (June 2025). Spec at **v1.0.0**. Strong adoption: 150+ supporting organizations (Microsoft, AWS, Salesforce, SAP, ServiceNow, IBM…), with native integration in Azure AI Foundry, Amazon Bedrock AgentCore, Google Cloud. IBM's ACP (BeeAI) **merged into A2A** in August 2025, consolidating the space. ([LF press release](https://www.linuxfoundation.org/press/linux-foundation-launches-the-agent2agent-protocol-project-to-enable-secure-intelligent-communication-between-ai-agents), [ACP joins A2A](https://lfaidata.foundation/communityblog/2025/08/29/acp-joins-forces-with-a2a-under-the-linux-foundations-lf-ai-data/))

**Gap vs. AI Nodes.** The Agent Card is the mature precedent for self-describing endpoint metadata, and A2A is the market-converged agent-to-agent layer. But: (a) it describes *agents* (skills, tasks), not *raw inference resources* — no model size, benchmarks, GPU, or per-token pricing fields (the spec explicitly leaves model metadata/pricing to extensions or out-of-band); (b) discovery is point-wise (fetch a card from a domain you already know) — there is **no standardized global/federated registry** for finding agents you don't already know about.

## 4. AGNTCY (Cisco → Linux Foundation)

**What it standardizes.** Open infrastructure for multi-agent systems: **Agent Directory** (a decentralized, content-addressed directory of agent records), **OASF — Open Agent Schema Framework** (attribute-based schema for agent capabilities, interactions, metadata; recently extended with Open Agent Specification support), **Agent Connect Protocol (ACP)** (invocation API spec — largely superseded in practice by A2A), plus identity (verifiable agent identity), SLIM messaging, and observability. ([LF press release](https://www.linuxfoundation.org/press/linux-foundation-welcomes-the-agntcy-project-to-standardize-open-multi-agent-system-infrastructure-and-break-down-ai-agent-silos), [GitHub](https://github.com/agntcy), [OASF](https://agentswelcome.dev/protocols/oasf), [Outshift blog](https://outshift.cisco.com/blog/ai-ml/open-agent-specification-support-and-deployment-data))

**Governance/maturity.** Under **Linux Foundation** since July 29, 2025; formative members Cisco, Dell, Google Cloud, Oracle, Red Hat; 65+ supporting companies. Real code, but far less production adoption than MCP/A2A; it positions itself as complementary infrastructure ("the Internet of Agents"), and its ACP has effectively lost to A2A as the wire protocol.

**Gap vs. AI Nodes.** AGNTCY's Agent Directory + OASF is the **closest existing analog to the AI Nodes registry idea** — a schema-driven, decentralized, vendor-neutral directory where capabilities are published for discovery. However, its records describe *agents/agentic software*, not inference endpoints: OASF has no first-class schema for model weights/size, GPU capacity, MLPerf-style benchmark scores, or per-token pricing, and no billing/settlement layer. Adoption is the open question.

## 5. ANP, NANDA, and other discovery conventions

**Agent Network Protocol (ANP).** Open-source (community-driven, originated in China; not under a major foundation) protocol for a decentralized agent network: W3C **DID-based identity** (`did:wba`), JSON-LD **Agent Description documents**, and an **Agent Discovery Service Protocol** — `/.well-known/agent-descriptions` returns a JSON-LD manifest of all agent description URLs on a domain (passive discovery), plus active registration to search services. Maturity: draft specs, niche adoption, cited in academic interoperability surveys as the "decentralized/semantic-web" pole of the A2A/ACP/ANP triangle. ([spec](https://agentnetworkprotocol.com/en/specs/08-anp-agent-discovery-protocol-specification/), [GitHub](https://github.com/agent-network-protocol/AgentNetworkProtocol))

**MIT Project NANDA.** MIT Media Lab initiative for the "Internet of AI Agents": the **NANDA Index**, a lean federated registry (registration, resolution, client-agent mapping) hosted across ~15 universities/partners, layered *on top of* MCP and A2A, with discovery/identity/federation/interoperability layers. Academic-stage with pilot deployments; papers on arXiv describe the architecture and enterprise use. ([MIT Media Lab overview](https://www-prod.media.mit.edu/projects/mit-nanda/overview/), [NANDA Index paper](https://arxiv.org/pdf/2507.14263), [The New Stack](https://thenewstack.io/how-mits-project-nanda-aims-to-decentralize-ai-agents/))

**Gap vs. AI Nodes.** These are the projects most ideologically aligned with "federated registry + discovery" — NANDA in particular is exactly a federated index. But both index *agents*, not compute/models: no GPU/pricing/benchmark metadata, no billing, and both have low adoption. They demonstrate the concept is recognized as unsolved, and that new entrants (AI Nodes) would compete with at least two funded attempts.

## 6. OpenAI-compatible API and `/v1/models`

**Status.** The OpenAI Chat Completions (and increasingly Responses) API shape is the unambiguous **de facto inference wire standard** — implemented by vLLM, Ollama, LiteLLM, TGI, and exposed natively by major non-OpenAI model vendors (DeepSeek, Qwen/DashScope, Kimi, GLM, MiniMax…). No standards body governs it; OpenAI can change it unilaterally. ([BentoML handbook](https://bentoml.com/llm/llm-inference-basics/openai-compatible-api), [Eden AI](https://www.edenai.co/post/why-openai-compatible-apis-are-the-new-standard))

**`/v1/models` as discovery.** It is the only widely deployed inference-discovery primitive: a client can enumerate model IDs a backend accepts. But it returns essentially **just IDs and ownership strings** — no size, context length (inconsistently), benchmarks, hardware, or pricing — it is per-endpoint (you must already know the base URL), and some providers omit it entirely. Aggregators fill the gap commercially: **OpenRouter** lists 300–375+ models behind one OpenAI-compatible API with per-token input/output pricing, provider routing/fallback, and a public models API including pricing metadata ([openrouter.ai/models](https://openrouter.ai/models)); Hugging Face's Inference Providers play a similar role. These are proprietary marketplaces, not standards.

**Gap vs. AI Nodes.** This layer gives AI Nodes its invocation format for free (any AI Nodes node would sensibly speak OpenAI-compatible + native APIs), and OpenRouter proves demand for cross-vendor model listing with pricing — but there is **no open, vendor-neutral standard** for the catalog itself: no standardized rich-metadata model listing, no federated registry, no open per-token settlement.

## 7. Cross-cutting primitives: identity, payments, capability delegation, model metadata

**W3C DIDs / Verifiable Credentials.** **DID v1.1 reached W3C Candidate Recommendation in March 2026**; VCs 2.0 are W3C Recommendations. Emerging agent-identity work builds on them: the **W3C Agent Identity Registry Protocol Community Group** (call for participation April 2026), **MCP-I donated to the Decentralized Identity Foundation** (March 2026), the draft **did:trail** method, and IETF individual drafts (agent identity registry, agents-as-workloads in WIMSE). All early-stage; identity for agents is coalescing around DIDs + Agent Cards + OAuth 2.1 delegation extensions. ([W3C CG](https://www.w3.org/community/agent-identity/), [IETF draft](https://datatracker.ietf.org/doc/draft-drake-agent-identity-registry/), [survey](https://zylos.ai/research/2026-03-07-ai-agent-identity-discovery-trust-frameworks))

**x402 (HTTP 402 machine payments).** Coinbase/Cloudflare protocol embedding stablecoin (USDC) payments in HTTP via the 402 status code — no accounts or cards, designed for agents and paid APIs, including **paid MCP tools** on Cloudflare. Governance moved to the **Linux Foundation's x402 Foundation (formalized April 2, 2026 at the MCP Dev Summit)**. Real traction: on the order of 10⁸ transactions across Base and Solana and tens of thousands of active agents by spring 2026 (volume figures vary by report, roughly $50M cumulative to ~$600M annualized depending on methodology). Apache-2.0 reference implementations in TS/Python/Go. This is the strongest existing answer to AI Nodes' "pricing per token" billing leg. ([Coinbase](https://www.coinbase.com/blog/coinbase-and-cloudflare-will-launch-x402-foundation), [Cloudflare docs](https://developers.cloudflare.com/agents/tools/payments/x402/), [2026 comparison](https://wavect.io/blog/x402-payments-comparison-2026/))

**UCAN.** User-Controlled Authorization Network — delegable, public-key-verifiable capability tokens (JWT-extended). Spec at **v1.0.0-rc.1**; implementations in TS/Rust/Go; used by Storacha/w3up and decentralized-storage projects. Niche adoption; relevant to AI Nodes only as an optional delegation mechanism. ([ucan.xyz](https://ucan.xyz/specification/), [ucan-wg/spec](https://github.com/ucan-wg/spec))

**Model metadata & benchmarks.** **Hugging Face model cards** (Markdown + YAML front-matter: pipeline task, license, base model, datasets, eval results) are the de facto model-metadata format, powering Hub filtering/discovery via the Hub API — but they describe *weights artifacts*, not *serving endpoints*, and the schema is loosely enforced (studies of 32K+ cards show highly uneven completion). **MLCommons MLPerf Inference v6.0** (results April 1, 2026; new gpt-oss-120b, text-to-video, VLM, and multi-turn/agentic-serving tests, interactive results dashboard) is the industry-standard *hardware/system* inference benchmark — it ranks systems, not hosted endpoints, and its results are not machine-consumable at endpoint-discovery time by any standard. ([HF model cards](https://huggingface.co/docs/hub/model-cards), [MLPerf v6.0](https://mlcommons.org/2026/04/mlperf-inference-v6-0-results/), [agentic inference](https://mlcommons.org/2026/07/agentic-inference-for-mlperf-inference/))

**IETF/W3C on AI service discovery specifically.** No chartered IETF working group or W3C Recommendation-track work standardizes *AI inference service* discovery. Existing pieces: the IANA-registered `/.well-known/agent-card.json` (A2A), individual IETF drafts on agent identity/naming (e.g., draft-drake-agent-identity-registry, draft-liu-dmsc-acps-arc), the W3C agent-identity CG, and academic proposals (Agent Name Service, agent URI schemes). All pre-standard.

## Gap Analysis: AI Nodes vs. the 2026 landscape

### Already covered (don't reinvent)

| AI Nodes component | Covered by |
|---|---|
| Inference invocation wire format (prompt + data in, completion out) | OpenAI-compatible API (de facto); MCP for tool calls; A2A v1.0 for agent tasks |
| Tool-server discovery & bridging target | MCP + official MCP Registry (API frozen v0.1; server.json, namespace auth, OpenAPI sub-registry interface) |
| Agent self-description at a known endpoint | A2A Agent Card at `/.well-known/agent-card.json` (IANA-registered); ANP JSON-LD agent descriptions |
| Machine-to-machine per-call payments | x402 (Linux Foundation, USDC over HTTP 402, live at scale, already wired into paid MCP tools) |
| Decentralized identity & signed attestations | W3C DID v1.1 (CR) + VC 2.0; UCAN for capability delegation |
| Benchmark methodology | MLPerf Inference v6.0 (systems), plus open eval harnesses/leaderboards (models) |
| Registry architecture patterns | MCP Registry's meta-registry + aggregator model; NANDA's federated index; AGNTCY Agent Directory |

### Partially covered

- **Registry of AI capabilities with schema'd metadata** — AGNTCY OASF/Agent Directory and NANDA Index do this for *agents*; the MCP Registry does it for *tool servers*. Nobody does it for *inference endpoints/compute*. The schema work (OASF) is extensible in principle but has no model/GPU/pricing attributes today.
- **Model metadata** — HF model cards standardize describing a *model artifact* (size, license, evals) but not a *served instance of it* (endpoint URL, latency, GPU class, price, availability). The endpoint↔artifact link is the missing join.
- **Pricing/billing discovery** — OpenRouter publishes per-token prices via API and does routing/fallback, proving the product; but it's a single proprietary marketplace, not an open standard, and x402 handles settlement but not *price advertisement in discovery metadata* (x402's 402 response does quote a price, but only per-request at call time, not for catalog browsing/ranking).
- **Federation** — MCP Registry federates by shared OpenAPI interface; NANDA federates an index across institutions. Both are early; neither carries the metadata AI Nodes needs.

### Genuinely uncovered (the actual white space)

1. **An open, vendor-neutral registry of *inference endpoints*** with rich, machine-readable metadata: model identity (linked to a HF-style card), parameter count, modality (LLM/diffusion/etc.), context window, quantization, backing GPU/hardware, benchmark scores, availability/SLA, and per-token price. No standard, no foundation project, and no draft spec targets this. The nearest things are proprietary (OpenRouter's catalog, cloud model gardens) or subject-mismatched (agent registries).
2. **Standardized ranking/curation signals** for such endpoints — the MCP Registry explicitly punts ratings to aggregators; A2A/AGNTCY/NANDA have no ranking layer; MLPerf scores aren't attached to discoverable endpoints.
3. **A discovery→invoke→pay loop as one standard**: composing catalog discovery + OpenAI-compatible invocation + x402 settlement exists only as bespoke integrations (e.g., Cloudflare paid MCP tools), not as a specified profile.
4. **Bridging discovered inference nodes to MCP servers and WebMCP sites** — nothing specifies this; note WebMCP itself is a pre-standard origin-trial API with near-zero deployment, so this leg is speculative.

### Strategic caveats

- The registry idea itself is crowded at the *agent* layer (MCP Registry, A2A cards, AGNTCY, NANDA, ANP — three of them Linux Foundation projects), so "AI Nodes" would need to position sharply as a **compute/model-endpoint registry**, not another agent registry, and ideally *reuse* rather than duplicate: OASF-style schemas or server.json-style records, A2A-style `/.well-known/` cards for passive discovery, DIDs for node identity, x402 for billing, OpenAI-compatible + MCP as invocation bindings.
- The strongest incumbent threat is not a standard but **OpenRouter-style marketplaces and hyperscaler model catalogs** already delivering the user-visible value (browse models, compare price/benchmarks, one API) without openness or federation.
- History in this space (ACP folding into A2A within a year; WebMCP's deployment gap) suggests consolidation is fast and adoption — not spec quality — decides winners; the viable path for a new standard is usually donation to an existing foundation (LF AI & Data hosts A2A, AGNTCY, and x402) rather than a standalone body.

**Bottom line:** every *ingredient* of AI Nodes exists as a standard or de facto practice, but the specific *composition* — a federated, open registry of inference endpoints carrying model + hardware + benchmark + per-token-price metadata, with a specified discover→invoke→pay flow and bridges into MCP/WebMCP — is genuinely unoccupied as of mid-2026.
